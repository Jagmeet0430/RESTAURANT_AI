# Billing and Receipts

Phase 12 expands this flow with End of Day settlement snapshots, receipt-width settings, printer test receipts, and configurable post-payment receipt opening. See `docs/BILLING_RECEIPTS_SETTLEMENT.md` for the current operator guide.

RestaurantAI uses one billing layer across restaurant orders and POS counter sales while keeping their source records separate.

## Workflow

1. Customer, kiosk, QR table, admin, or POS creates a sale.
2. Kitchen workflow continues independently through Confirmed, Accepted, Preparing, Ready, and Completed.
3. Cashier opens Admin -> Bills.
4. Cashier reviews unpaid orders or table dues.
5. Cashier selects Cash, UPI, Card, or Pay at Counter and confirms the amount.
6. RestaurantAI marks the payment paid, updates the bill, and opens a receipt that can be printed or reprinted.

Payment status and order status are separate. Marking an order paid does not change its kitchen status.

## Billing Sources

Restaurant orders remain in `orders` and have persisted bill rows in `bills`.

POS/counter sales remain in `counter_sales` and `counter_sale_items`. New POS sales also write one paid row in `payments` with `source_type = 'counter_sale'` and `source_id = counter_sales.id` so end-of-day payment totals reconcile.

POS sales are not forced into restaurant orders.

## Bill Numbers

Order bills use:

```text
BILL-YYYY-000001
```

POS bills use:

```text
POS-YYYY-000001
```

The sequence is generated by PostgreSQL and is independent from browser state.

## Tax and Totals

Receipts print stored sale totals:

- Subtotal
- Discount
- GST/tax
- Packing or delivery charge
- Grand total

RestaurantAI stores GST/tax amounts on the order or POS sale at creation time. This release does not add a second global tax-rate engine because the existing checkout/POS flows already persist tax amounts on each sale.

## Table Settlement

Admin -> Bills shows unpaid dine-in/table QR orders grouped by table.

Settle Table locks all unpaid non-cancelled orders for that table inside a database transaction, verifies the confirmed amount, marks each order paid, and refreshes its bill. Historical paid orders are not included.

## Individual Settlement

Use Pay Order from Admin -> Bills for one unpaid order. The existing mark-paid endpoint delegates to the same idempotent settlement service.

Cancelled orders cannot be settled as normal sales.

## Payment Methods

Offline methods:

- Cash
- UPI
- Card
- Pay at Counter

Online Razorpay payments remain optional and are not required for offline/LAN operation.

## Split and Partial Payments

Split payments and partial payments are deferred. The current production-safe Phase 10 flow settles one order or one table amount in full with one selected method. This avoids introducing multi-row payment allocation without a broader refund/balance workflow.

## Receipts

Admin receipt route:

```text
/admin/receipt/order/:orderId
/admin/receipt/counter_sale/:saleId
```

The receipt uses restaurant settings for:

- Restaurant name
- Address
- Phone
- GSTIN, when configured
- Footer text

Do not invent a GSTIN. Leave it blank in Settings when the restaurant has not configured one.

## Printing

Receipts are browser-printable and work offline with:

- USB thermal printer
- Windows printer driver
- Browser print dialog

Use the Paper selector on the receipt page for 80mm or 58mm preview. The print stylesheet hides Admin navigation, sidebars, buttons, and browser-only controls so only the receipt is printed.

80mm is the primary supported layout. 58mm is supported with narrower columns and smaller type where practical.

## Reprint

Paid bills show Reprint from Admin -> Bills. Reprinting opens the existing receipt and does not create another payment.

## Kiosk and QR Compatibility

Kiosk pay-at-counter orders and table QR orders are submitted as unpaid orders. Cashier settlement happens in Admin -> Bills. Kiosk and QR customers do not print receipts directly.

Table QR receipts include the table number and order number.

## End-of-Day Summary

Admin -> Bills shows the live payment summary. Admin -> End of Day adds drawer cash comparison and stores daily settlement history.

- Cash sales
- UPI sales
- Card sales
- Total collected
- Unpaid orders

New order and POS payments are summed from `payments`.

## Offline Use

Billing, payment marking, receipt pages, and browser printing are local app features. They do not require cloud printer APIs or internet connectivity.

## Troubleshooting

If a receipt does not print:

- Confirm the printer is installed in Windows.
- Print a Windows test page.
- Confirm the browser can see the printer in the print dialog.
- Select the correct paper width in the receipt page.
- Reprint from Admin -> Bills after refreshing the page.

## Hardware Test Status

No physical USB thermal printer was available during implementation. Hardware validation is pending and should be completed during restaurant pilot testing.
